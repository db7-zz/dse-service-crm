# S2 服务进度迁移回滚说明

本迁移包含 S1 历史任务到 S2 阶段状态的不可逆推导。生产执行前必须完成数据库备份，并将回滚定义为“恢复整库备份”，不得尝试在已有 S2 业务写入后直接删除新列或转换记录。

## 执行前

1. 停止 API 写流量。
2. 运行 `pnpm --filter @dse/database s2:migration:preview`，保存 JSON 结果。
3. 完成 PostgreSQL 物理或逻辑备份并验证可恢复。
4. 记录当前迁移版本和应用镜像版本。

## 验证

迁移完成后运行 `pnpm --filter @dse/database s2:migration:verify`。只有 `summaryMismatchCount` 为 `0`、每名已启用学生最多一个进行中阶段且预览数量与实际一致时，才恢复写流量。

## 回滚

若迁移或验收失败：

1. 保持 API 写流量停止。
2. 恢复迁移前已验证的整库备份。
3. 部署 S1 应用镜像。
4. 再次核对学生、任务、负责人、截止时间和时间线数量。

不要对 `stage_transitions`、计算批次或任务表执行人工批量删除；这些记录一旦与 S2 写入混合，只能通过备份恢复保持审计一致性。
