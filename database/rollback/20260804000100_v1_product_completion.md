# V1.0产品补全迁移回滚说明

迁移：`20260804000100_v1_product_completion`

## 原则

本迁移新增大量可产生业务数据的表和枚举值。PostgreSQL不能安全地直接删除已加入的枚举值，因此不提供自动向下迁移脚本。生产回滚采用“应用回退 + 兼容保留”或“整库恢复”，禁止直接删除新表。

## 应用回退

1. 停止写入并记录迁移后新增业务数据量。
2. 将应用切回上一个已验证版本。
3. 保留新表、新字段和新枚举；旧应用不会引用它们。
4. 验证登录、学生、SOP、任务和监督看板。
5. 修复后重新部署V1应用，不重复手工修改迁移历史。

此方式适用于迁移成功但应用层需要快速回退，且此前版本的Prisma查询不会选择新增字段。

## 整库恢复

如迁移本身损坏数据或必须完全回到迁移前状态：

1. 停止全部应用写入。
2. 按 `docs/operations/BACKUP_RESTORE.md` 校验迁移前备份。
3. 在全新的空数据库中恢复，不覆盖唯一可用备份。
4. 将应用连接切到恢复库。
5. 执行迁移状态、健康检查、管理员登录、任务监督和学生详情验证。
6. 保留原故障库用于审计，待批准后再逐文件、逐资源处置。

## 数据导出

若迁移后已产生资料、申请、问题、通知或确认数据，回到旧应用前应先导出这些新增表用于后续人工合并。导出文件包含个人信息，必须加密存放、限制访问并登记操作人。
