# ADR-004：S1 管理员角色归并与权限基线

**状态：** Accepted

**日期：** 2026-07-30

本决策自 S1 起取代 ADR-003 中 `ERIC_MANAGER` 作为独立监督角色的部分；ADR-003 的
S0 RBAC 结构、后端 Guard 和业务关系二次校验原则继续有效。

## 背景

S0 为技术底座保留了 `ADMINISTRATOR` 和 `ERIC_MANAGER` 两个内部管理角色。
S1 的任务监督闭环确认管理员是唯一管理和监督主体，因此不能继续按两个角色分配页面、
接口或数据权限。

## 决策

- `ADMINISTRATOR` 是 S1 唯一管理员角色和监督权限主体；
- 有效的 `ERIC_MANAGER` 用户角色关系在升级时归并为 `ADMINISTRATOR`；
- `ERIC_MANAGER` 角色代码、已过期关系和审计日志值仅为历史追溯保留，不再用于新账号；
- 管理员获得学生、SOP、服务启用、任务监督和逾期提醒权限；
- 管家只获得本人任务的读取与执行权限；
- 规划老师和其他基础角色不获得 S1 权限；
- 前端仅按权限隐藏入口，后端 Guard 仍是强制授权边界，拒绝请求返回 `403` 并写入安全审计。

## S1 权限

管理员权限：

- `students.read`
- `students.write`
- `sop.read`
- `sop.write`
- `service.activation.write`
- `tasks.supervision.read`
- `tasks.supervision.write`
- `overdue-alerts.read`
- `overdue-alerts.write`

管家权限：

- `tasks.own.read`
- `tasks.own.write`

`supervision.access` 作为 S0 历史权限代码保留，但不再授予 S1 页面、菜单或接口访问能力。

## 数据权限

权限代码只表达功能能力。后续任务接口还必须在服务端校验任务负责人关系：

- 管理员可读取全部 S1 任务并执行监督操作；
- 管家仅可读取和执行 `assignee_id` 等于本人用户 ID 的任务；
- 转派生效后，原管家立即失去该任务权限。

任务关系校验与具体业务表、接口一起在后续纵向功能 Issue 中实现，不能依赖前端过滤代替。

## 迁移与审计

迁移通过唯一约束和冲突处理保持幂等，不重复创建用户或用户角色关系。原
`ERIC_MANAGER` 关系标记为过期而非物理删除，既有审计日志的 `operator_role` 不更新。
生产回滚必须按账号人工核对，不得物理删除审计事实。
