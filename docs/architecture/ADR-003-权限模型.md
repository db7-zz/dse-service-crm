# ADR-003：RBAC与业务关系权限

**状态：** Accepted  
**日期：** 2026-07-28

## 决策

S0使用角色、权限、用户角色和角色权限四层RBAC。前端根据权限构建菜单和路由，后端使用
声明式权限装饰器和Guard强制校验。

固定角色：

- `ADMINISTRATOR`：管理员端和系统管理。
- `ERIC_MANAGER`：业务负责人和监督管理端。
- `BUTLER`：管家。
- `PLANNER`：规划老师。
- `SPECIALIST`：专项老师。
- `STUDENT`：学生。

基础权限：

- `workspace.access`
- `supervision.access`
- `system.users.read`
- `system.users.write`
- `system.audit.read`
- `portal.access`

## 数据权限

S0不引入学生或任务对象。Guard接口保留授权上下文，后续阶段在RBAC之后叠加学生负责人、
任务负责人和专项任务关系校验。

## 命名

具体人员姓名不能作为系统端、模块或API命名。业务负责人角色对应“监督管理端”和
“监督管理看板”。
