# DSE升学服务CRM v0.3.0

## 版本主题

S2把S1静态的八阶段任务分组升级为可解释、可审计的学生服务进度。阶段完全由阻塞任务终态计算，不提供人工推进、回退或强制完成。

## 主要能力

- SOP草稿可配置任务是否阻塞阶段，每个阶段发布前必须至少有一项阻塞任务。
- 服务启用后第一阶段自动开始，任务完成或取消后在同一事务中推进阶段。
- 支持后续阶段任务提前执行和满足条件后的连续推进。
- 非阻塞任务不影响推进，阶段完成后未终态任务作为前序遗留继续监督。
- 管理员可创建阻塞属性不可变的临时管家任务。
- 学生列表和详情展示当前阶段、`X/8`进度、阻塞、逾期、遗留和任务完成率。
- 管家通过“学生管理”只读查看本人当前负责学生，权限按`default_butler_id`服务端过滤。
- 增加阶段转换历史、计算异常、受控重算、迁移预览和迁移后一致性验证。
- 迁移遇到阶段数量、顺序、任务缺失或跨学生关联异常时标记为错误，不生成猜测进度。

## 升级步骤

1. 停止API写流量并完成数据库备份。
2. 运行`pnpm --filter @dse/database s2:migration:preview`并保存结果。
3. 部署迁移`20260803000100_s2_service_progress`。
4. 运行`pnpm db:generate`与`pnpm --filter @dse/database s2:migration:verify`。
5. 验证`summaryMismatchCount = 0`后部署API与Web。
6. 使用管理员和管家账号完成S2验收流程。

## 兼容与限制

- 既有S1 SOP任务和任务实例默认迁移为阻塞，任务状态、负责人、截止时间和历史不改变。
- S2不包含服务暂停/恢复、手工阶段操作、资料或申请阻塞、多角色任务、规划老师进度页、学生端、导出和外部通知。
- 回滚必须恢复迁移前整库备份，不能通过批量删除新增记录替代。
