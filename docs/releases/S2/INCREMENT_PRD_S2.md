### 0.1 文档定位

本文档仅描述 S2 相对产品总 PRD 和 S1 新增或调整的业务规则、页面、数据、权限、接口、迁移及验收要求，不重复抄写完整产品总 PRD。

当本文档与 S1 在 S2 增量范围内存在冲突时，以本文档为准；未被本文档修改的账号、认证、RBAC、任务状态机、任务操作权限、逾期计算、提醒、幂等、乐观并发、审计和工程规范继续继承 S0、S1 及总 PRD。

### 0.2 S1 实现基线

S2 以 S1 已验收的真实实现为前提，不将规划能力误写为现有能力：

- S1 已实现固定八阶段 SOP、服务启用、八个阶段实例和全部任务实例的一次性事务生成；
- S1 所有 SOP 任务的负责角色固定为管家；
- 有默认管家时，任务实例自动分配给该管家；没有默认管家时保持待分配；
- S1 阶段实例仅组织任务，没有阶段状态、当前阶段或自动推进；
- S1 所有阶段任务在服务启用时一次生成，截止时间均从服务启用时间计算；
- 后续阶段任务在 S1 中可以提前查看和执行；
- S1 完成标准仅作为文字提示，系统以任务主状态作为执行结果，不校验附件或资料；
- S1 不支持服务暂停、恢复或撤销启用；
- S1 不支持手工新建临时任务；
- S1 管家只有本人任务访问能力，没有学生管理页和本人负责学生详情权限；
- S1 规划老师没有任务或学生服务进度页面；
- S1 已有任务完成、取消、改期、转派、逾期、幂等、事务和 `409 Conflict` 基础能力。

### 0.3 术语统一

- 服务进度：八个阶段按顺序形成的学生服务执行结果。
- 阶段实例：SOP 套用于学生时生成的阶段快照；S2 为其增加状态和时间。
- 当前阶段：按顺序第一个尚未完成的阶段；全部完成后为空。
- 阻塞任务：未进入终态时阻止所属阶段完成的任务。
- 非阻塞任务：计入任务统计和监督，但不阻止阶段完成。
- 任务终态：`COMPLETED` 或 `CANCELED`。
- 前序遗留任务：所属阶段已经完成，但任务自身仍为 `TODO` 或 `IN_PROGRESS` 的非阻塞任务。
- 连续推进：当前阶段完成后，若后续阶段的阻塞任务已提前全部进入终态，系统继续按顺序完成后续阶段，直至遇到仍有未终态阻塞任务的阶段或八阶段全部完成。
- 临时任务：管理员在学生启用服务后手工创建的个性化管家任务；它不是 SOP 模板生成任务。
- 阶段计算：根据阶段顺序和阻塞任务终态，计算阶段状态、当前阶段、阶段时间和完成原因。

## 2. 为什么增加 S2

### 2.1 当前问题

S1 已能把管理员发布的 SOP 转换为具体学生的管家任务，并记录执行、逾期和介入过程，但阶段实例仍是静态分组。管理员无法快速确认学生当前走到哪个阶段、哪些任务正在阻止推进、是否存在前序遗留任务，也无法从任务结果得到稳定的学生服务进度。

管家虽然可以执行本人任务，但没有按本人负责学生查看完整八阶段进度的入口，难以在学生维度理解当前重点和后续工作。

### 2.2 阶段目标

S2 需要形成以下闭环：

1. 管理员在 SOP 草稿中配置每项任务是否阻塞阶段；
2. 发布时保证每个阶段至少存在一项阻塞任务；
3. 学生启用服务时生成带阻塞快照的任务和带状态的阶段实例；
4. 管家继续在 S1 任务中心执行具体任务；
5. 任务完成或取消后，系统在同一事务中计算并推进阶段；
6. 非阻塞任务未完成时允许阶段推进，并作为前序遗留任务继续监督；
7. 管理员在学生列表和详情中查看当前阶段、阶段进度、阻塞、逾期和完整时间线；
8. 管家从“学生管理”查看本人负责学生的只读服务进度；
9. 管理员可创建个性化临时管家任务，并按规则决定是否阻塞当前或后续阶段；
10. 所有阶段变化、重算、异常和人工任务创建均可追溯。

### 2.3 成功判定

S2 完成时，应能以一个已启用服务的学生为对象，从管家完成或管理员取消阻塞任务开始，自动完成当前阶段、启动下一阶段、连续处理已提前完成的后续阶段，并在管理员和对应管家的页面上展示一致、可解释、可审计的服务进度。

## 4. 使用角色与权限变化

| 角色                      | S2 可见数据                                                                      | S2 可执行操作                                                                            |
| ------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 管理员（`ADMINISTRATOR`） | 全部学生服务摘要、八阶段状态、任务、阶段历史、计算异常和迁移结果                 | 配置阻塞属性；创建临时任务；查看、筛选、排序；继续执行 S1 已授权的任务介入；触发受控重算 |
| 管家                      | `default_butler_id` 为本人的学生及其服务摘要、八阶段任务和本人有权查看的任务详情 | 只读查看学生服务进度；继续执行 S1 本人任务操作                                           |
| 规划老师                  | S2 不开放服务进度、阶段历史或任务处理记录                                        | 无 S2 操作权限                                                                           |
| 其他角色                  | 无 S2 业务数据                                                                   | 不得访问 S2 页面和接口                                                                   |

### 4.1 管家学生行级范围

- “本人负责学生”仅以学生当前 `default_butler_id = 当前用户 ID` 判断；
- 管家不能通过任务负责人关系扩大到其他学生的完整服务进度；
- 更换默认管家后，新管家立即获得该学生服务进度权限，原管家立即失去；
- 原管家仍可按 S1 规则访问尚未被转派且仍由本人负责的任务，但不能继续访问该学生完整服务进度；
- 管家列表、详情、筛选、排序和计数均必须在后端先应用行级范围，不能先查全量再由前端过滤；
- 管家无权查看的任务不返回详情字段，不得通过阶段聚合泄露任务标题、说明、时间线或负责人。

### 4.2 页面权限

- 管理员与管家均可看到一级菜单“学生管理”；
- 管理员进入现有全量学生管理页；
- 管家进入相同视觉和信息架构的本人负责学生页，不新增“我的学生”一级菜单；
- 管家页面隐藏新建、编辑、分配负责人、启用服务、创建临时任务、批量分配和重算等管理员操作；
- 规划老师不显示“学生管理”中的 S2 服务进度入口；
- 菜单隐藏不能代替接口鉴权；
- 越权访问返回 `403 Forbidden` 并按 S0/S1 规范记录关键安全审计。

## 5. 核心业务规则

### 5.1 SOP 阻塞任务配置

1. SOP 草稿的每项任务增加“是否阻塞阶段”开关；
2. 新增 SOP 任务默认设置为阻塞；
3. 管理员可在草稿发布前修改该属性；
4. 复制新版本时完整复制阻塞属性；
5. 已发布和已停用版本的阻塞属性只读；
6. 发布校验要求八个阶段中的每个阶段至少存在一项阻塞任务；
7. 不允许发布零阻塞任务的阶段，避免学生启用后阶段无依据地自动跳过；
8. 学生启用服务时，将阻塞属性复制到任务实例快照；
9. 后续 SOP 版本变化不影响已生成任务实例。

### 5.2 阶段状态

阶段实例状态仅允许：

```text
NOT_STARTED -> IN_PROGRESS -> COMPLETED
```

规则：

- 阶段状态只能由系统计算，不提供业务用户写接口；
- 服务启用成功后，第一阶段为 `IN_PROGRESS`，其余阶段为 `NOT_STARTED`；
- 一个学生同一时刻最多存在一个 `IN_PROGRESS` 阶段；
- 已完成阶段不能回退或重新打开；
- 全部八阶段完成后，不再存在当前阶段，页面显示“8/8，全部阶段已完成”；
- 学生服务状态仍为 S1 的 `ENABLED`，S2 不新增“已完成”服务状态；
- 未启用学生没有阶段状态，页面显示“服务未启用”。

### 5.3 阶段完成条件

- 当前阶段内全部阻塞任务均进入 `COMPLETED` 或 `CANCELED` 时，阶段完成；
- 阻塞任务处于 `TODO` 或 `IN_PROGRESS` 时，阶段不能完成；
- 非阻塞任务无论处于何种状态均不影响阶段完成；
- 取消阻塞任务与完成阻塞任务一样满足终态条件，但取消原因和操作人必须继续按 S1 保留；
- 阶段完成不要求任务附件、资料审核或其他结构化凭证；
- 阶段完成以服务器中的任务终态为唯一计算依据；
- S3、S4 接入资料和申请阻塞前，不得用未实现的资料完整性或申请状态阻止阶段推进。

### 5.4 自动推进与连续推进

1. 管家完成任务或管理员取消任务时，系统判断该任务是否为当前阶段阻塞任务；
2. 若不是，任务按 S1 正常进入终态，阶段不变化；
3. 若是但当前阶段仍有其他未终态阻塞任务，阶段保持 `IN_PROGRESS`；
4. 若是最后一个未终态阻塞任务，系统在同一事务中：
   - 完成当前阶段；
   - 记录完成时间和触发原因；
   - 将下一阶段设为 `IN_PROGRESS` 并记录开始时间；
   - 检查下一阶段阻塞任务是否已提前全部进入终态；
   - 若已满足，则立即完成该阶段并继续检查后续阶段；
   - 直至遇到仍有未终态阻塞任务的阶段或八阶段全部完成。
5. 任务状态、任务时间线、阶段状态、阶段转换记录和审计日志必须在同一业务事务中提交；
6. 阶段计算失败时，本次任务完成或取消也必须回滚，不得出现任务已终态但阶段未更新的部分成功；
7. 重复请求、页面刷新或后台重算不得重复生成阶段转换记录；
8. 并发完成、取消、创建阻塞任务或推进同一阶段时，只有首个合法事务成功，过期请求返回 `409 Conflict`。

### 5.5 后续阶段任务提前执行

- S1 已一次生成全部八阶段任务，S2 继续允许查看和执行后续未开始阶段任务；
- `NOT_STARTED` 只表示阶段尚未成为当前阶段，不表示其任务不可执行；
- 后续阶段任务提前完成或取消时，只更新任务自身，不直接跳过前序阶段；
- 当所有前序阶段完成后，系统按 5.4 规则检查该阶段并允许连续推进；
- 后续阶段任务提前终态的实际时间保留，不改写为阶段开始时间；
- 因提前完成而被连续推进的阶段，`started_at` 与 `completed_at` 可相同；
- 该阶段完成原因必须标记为“前序阶段完成后，本阶段阻塞任务已全部进入终态”。

### 5.6 前序遗留任务

- 阶段完成时仍未终态的非阻塞任务成为前序遗留任务；
- 前序遗留任务继续保留原状态、负责人、截止时间、逾期、延期、时间线和 S1 操作权限；
- 前序遗留任务可以继续开始、更新、报备、完成、改期、转派或取消；
- 前序遗留任务不导致已完成阶段回退，也不阻止当前或后续阶段推进；
- 页面应明确展示其来源阶段，不能把它误显示为当前阶段任务；
- 遗留任务完成或取消后，从“前序遗留任务数”中移除，但历史继续保留。

### 5.7 临时任务

S2 将手工临时任务明确列为新增能力，不视为 S1 已有功能。

创建规则：

- 仅管理员可以为已启用服务的学生创建；
- 任务负责角色固定为管家；
- 必须选择所属阶段、任务名称和当前截止时间；
- 任务说明、完成标准和负责人可选；
- 负责人为空时沿用 S1 待分配规则；
- 当前截止时间必须晚于提交时的当前时间，精确到分钟；
- 临时任务主状态初始为 `TODO`；
- 默认是非阻塞任务；
- 管理员可在创建时设置为阻塞任务；
- 阻塞属性在任务创建后不可修改；
- 管理员不能为未启用学生创建临时任务。

阶段约束：

- 当前阶段或尚未开始阶段可创建阻塞或非阻塞任务；
- 已完成阶段只能创建非阻塞跟进任务；
- 已完成阶段新增任务不得导致阶段回退；
- 八阶段全部完成后仍可创建非阻塞跟进任务，但不得新增阻塞任务；
- 并发创建阻塞任务与阶段推进时必须校验阶段版本；阶段已完成则创建请求返回 `409 Conflict`，不得静默改为非阻塞；
- 临时任务创建成功后进入现有任务中心、学生详情、监督看板和统计口径；
- 临时任务后续执行、改期、转派、取消、逾期、提醒、幂等和审计全部继承 S1；
- 管理员仍不能代替管家开始、更新或完成临时任务。

### 5.8 不支持的阶段操作

S2 不提供：

- 手工开始阶段；
- 手工完成阶段；
- 强制跳过阶段；
- 回退或重新打开阶段；
- 修改阶段开始或完成时间；
- 删除阶段实例；
- 在学生已启用后修改其阶段顺序；
- 将学生同步到新 SOP；
- 通过修改任务阻塞属性纠正历史。

数据异常只能通过受控重算或数据修复流程处理，并保留审计。

- 该学生全部未终态逾期任务数；

筛选：

排序：

未启用学生：

- 创建成功后刷新摘要和对应阶段。

- 草稿可编辑；
- 新增任务默认开启；
- 已发布和已停用版本只读；
- 发布校验失败时定位到没有阻塞任务的阶段；

- 加载中；
- 空数据；
- 接口失败及重试；
- 无权限；
- 学生不存在或已删除；
- 服务未启用；
- 进度计算中；
- 进度数据异常；

## 7. 统计口径

### 7.1 阶段进度

```text
阶段进度 = 已完成阶段数 ÷ 8
```

页面优先展示 `X/8`，百分比仅作为辅助，不得只显示单一百分比。

### 7.2 当前阶段阻塞任务数

仅统计：

- 所属阶段为当前阶段；
- `is_blocking = true`；
- 状态为 `TODO` 或 `IN_PROGRESS`。

后续未开始阶段的阻塞任务不计入学生当前阻塞数。

### 7.3 逾期任务数

统计该学生全部状态为 `TODO` 或 `IN_PROGRESS` 且当前已逾期的任务，包括：

- 当前阶段任务；
- 后续未开始阶段任务；
- 前序遗留任务；
- SOP 生成任务；
- 临时任务。

逾期判断完全沿用 S1，不增加阶段逾期。

### 7.4 前序遗留任务数

统计：

- 所属阶段状态为 `COMPLETED`；
- `is_blocking = false`；
- 任务状态为 `TODO` 或 `IN_PROGRESS`。

### 7.5 任务完成率

```text
任务完成率 = 已完成任务数 ÷（任务总数 - 已取消任务数）
```

- SOP 任务和临时任务均纳入；
- 阻塞与非阻塞任务均纳入；
- 已取消任务不进入分子和分母；
- 分母为 0 时显示 `—`，不显示虚假的 `100%`；
- 任务完成率不参与阶段推进。

### 7.6 时间和耗时

- 阶段耗时按 `completed_at - started_at` 计算；
- 进行中阶段按当前服务器时间减 `started_at` 动态展示；
- 未开始阶段不展示耗时；
- 数据库存储 UTC，页面转为 `Asia/Hong_Kong`；
- 连续推进导致开始和完成时间相同时，耗时显示“不足1分钟”；
- 迁移推导时间必须带迁移来源标记。

## 8. 字段与数据变化

以下为逻辑模型；具体命名可由技术设计调整，但语义、约束、快照和历史要求不得删除。

### 8.1 SOP 任务模板

新增：

| 字段          | 必填 | 规则                                    |
| ------------- | ---- | --------------------------------------- |
| `is_blocking` | 是   | 布尔值；新增任务默认 `true`；发布后只读 |

发布约束：每个阶段至少一项 `is_blocking = true` 的任务。

### 8.2 阶段实例

新增：

| 字段           | 必填 | 规则                                      |
| -------------- | ---- | ----------------------------------------- |
| `status`       | 是   | `NOT_STARTED`、`IN_PROGRESS`、`COMPLETED` |
| `started_at`   | 否   | 进入进行中时记录                          |
| `completed_at` | 否   | 完成时记录                                |
| `version`      | 是   | 乐观锁，默认 0                            |

约束：

- `NOT_STARTED`：`started_at`、`completed_at` 均为空；
- `IN_PROGRESS`：`started_at` 非空，`completed_at` 为空；
- `COMPLETED`：`started_at`、`completed_at` 均非空；
- 同一服务启用记录最多一个 `IN_PROGRESS` 阶段；
- 状态只能按顺序前进。

### 8.3 学生服务启用记录

新增：

| 字段                        | 必填 | 规则                               |
| --------------------------- | ---- | ---------------------------------- |
| `current_stage_instance_id` | 否   | 当前进行中阶段；全部完成时为空     |
| `completed_stage_count`     | 是   | `0–8`，与阶段状态同事务维护        |
| `progress_version`          | 是   | 服务进度刷新和乐观并发令牌         |
| `calculation_status`        | 是   | `NORMAL`、`RECALCULATING`、`ERROR` |
| `calculation_error_code`    | 否   | 仅内部和管理员诊断使用             |
| `last_calculated_at`        | 否   | 最近成功计算时间                   |

`current_stage_instance_id` 和 `completed_stage_count` 是为列表查询维护的进度摘要，阶段实例及其转换记录仍是阶段历史的权威事实。两者必须在同一事务中保持一致。

### 8.4 任务实例

新增或调整：

| 字段                               | 必填 | 规则                                                 |
| ---------------------------------- | ---- | ---------------------------------------------------- |
| `source_type`                      | 是   | `SOP`、`MANUAL`                                      |
| `is_blocking_snapshot`             | 是   | 实例创建后不可修改                                   |
| `task_template_id`                 | 否   | SOP 任务必填，临时任务为空                           |
| `completion_window_hours_snapshot` | 否   | SOP 任务必填，临时任务为空                           |
| `created_by_id`                    | 否   | 临时任务必填；SOP 系统生成任务可为空或记录启用管理员 |

约束：

- `source_type = SOP` 时必须有关联模板和完成时限快照；
- `source_type = MANUAL` 时模板和完成时限快照为空；
- 所有任务仍必须关联学生、服务启用记录和阶段实例；
- 所有任务仍使用 S1 任务主状态、负责人、截止时间、版本和历史模型。

### 8.5 阶段转换记录

新增只追加记录：

| 字段                 | 必填 | 规则                                                                                                        |
| -------------------- | ---- | ----------------------------------------------------------------------------------------------------------- |
| `id`                 | 是   | 主键                                                                                                        |
| `stage_instance_id`  | 是   | 关联阶段                                                                                                    |
| `from_status`        | 否   | 首次启动可为空                                                                                              |
| `to_status`          | 是   | `IN_PROGRESS` 或 `COMPLETED`                                                                                |
| `trigger_type`       | 是   | `SERVICE_ACTIVATION`、`TASK_COMPLETED`、`TASK_CANCELED`、`CONTINUOUS_ADVANCE`、`MIGRATION`、`RECALCULATION` |
| `trigger_task_id`    | 否   | 由任务触发时记录                                                                                            |
| `summary`            | 是   | 可展示的触发说明                                                                                            |
| `calculation_run_id` | 否   | 迁移或重算批次                                                                                              |
| `created_at`         | 是   | UTC                                                                                                         |

幂等约束应防止同一阶段、目标状态和同一计算批次重复写入。

### 8.6 阶段计算批次

为迁移、异常重算和可观测性新增计算批次，至少记录：

- 批次 ID；
- 类型：`MIGRATION`、`RECALCULATION`；
- 学生或服务启用记录；
- 发起人或系统；
- 开始、结束时间；
- 执行状态；
- 变更摘要；
- 错误代码和内部错误摘要；
- 请求 ID。

普通业务用户不能修改或删除计算批次。

## 9. 接口变化

接口继续使用 `/api/v1` 和 `ApiEnvelope<T>`。

### 9.1 管理员学生进度

- `GET /api/v1/students`
  - 增加当前阶段、阶段进度、当前阻塞数、逾期数、遗留数；
  - 增加 `current_stage_code`、`has_current_blockers`、排序和分页参数。
- `GET /api/v1/students/{studentId}`
  - 增加服务进度摘要。
- `GET /api/v1/students/{studentId}/service-progress`
  - 返回八阶段、阶段状态、时间、任务分组、完成原因和计算状态。
- `POST /api/v1/students/{studentId}/manual-tasks`
  - 管理员创建临时任务。
- `POST /api/v1/students/{studentId}/service-progress/recalculate`
  - 仅管理员在数据异常时触发受控重算；
  - 正常状态下不得作为日常操作使用。

### 9.2 管家本人负责学生

- `GET /api/v1/my/students`
  - 只返回 `default_butler_id` 为当前管家的学生；
  - 支持与管理员列表一致的 S2 筛选、排序和分页子集。
- `GET /api/v1/my/students/{studentId}`
  - 返回 S1 允许的最小学生信息和 S2 服务摘要。
- `GET /api/v1/my/students/{studentId}/service-progress`
  - 返回本人负责学生的只读八阶段进度；
  - 任务详情仍按 S1 当前任务负责人权限单独校验。

不直接向管家授予管理员全量 `students.read` 权限。

### 9.3 SOP

沿用 S1 SOP 接口，任务 DTO 增加：

- `is_blocking`；
- 发布校验错误 `STAGE_BLOCKING_TASK_REQUIRED`。

### 9.4 任务终态操作

沿用 S1：

- `POST /api/v1/tasks/{taskId}/complete`
- `POST /api/v1/admin/tasks/{taskId}/cancel`

响应增加：

- 任务最新版本；
- 是否触发阶段变化；
- 最新当前阶段；
- 已完成阶段数；
- 连续推进的阶段列表；
- 学生服务进度版本或等价刷新令牌。

### 9.5 错误语义

至少增加：

| 场景                   | HTTP       | 业务错误                         |
| ---------------------- | ---------- | -------------------------------- |
| 阶段没有阻塞任务       | 422        | `STAGE_BLOCKING_TASK_REQUIRED`   |
| 未启用学生创建临时任务 | 409        | `SERVICE_NOT_ENABLED`            |
| 已完成阶段创建阻塞任务 | 409        | `STAGE_ALREADY_COMPLETED`        |
| 阶段并发变化           | 409        | `STAGE_VERSION_CONFLICT`         |
| 进度数据不一致         | 409 或 422 | `SERVICE_PROGRESS_INCONSISTENT`  |
| 管家访问非本人负责学生 | 403        | `FORBIDDEN`                      |
| 计算正在进行           | 409        | `SERVICE_PROGRESS_RECALCULATING` |

前端不得把 `409` 当作普通失败后自动重试写操作。

## 10. 事务、幂等与一致性

### 10.1 服务启用

S1 服务启用事务增加：

- 为阶段实例写入初始状态；
- 第一阶段记录启动事件；
- 为任务实例复制阻塞快照和来源类型；
- 更新最近计算时间；
- 返回初始当前阶段和 `0/8` 进度。

任一步失败继续整次回滚。

### 10.2 任务完成和取消

- 任务终态变化和阶段计算使用同一数据库事务；
- 先锁定或乐观校验任务及当前阶段版本；
- 阶段转换按顺序执行；
- 事务成功后前端才显示任务完成或取消成功；
- 事务失败时不保留部分任务或阶段变化；
- 相同幂等键重复提交返回首次成功结果，不重复推进或写日志；
- 连续推进产生的多条转换记录属于同一请求 ID 和计算上下文。

### 10.3 临时任务创建

- 支持幂等键；
- 校验学生服务状态、阶段归属、阶段状态和阶段版本；
- 创建任务、初始时间线和审计日志在同一事务；
- 新增当前阶段阻塞任务后，立即反映在摘要和阶段计算中；
- 相同请求不得重复创建任务。

### 10.4 查询一致性

- 学生列表摘要和详情摘要使用同一统计口径；
- 阶段状态以阶段实例为权威来源；
- 任务数量以当前任务数据实时或一致性聚合计算；
- 不允许列表显示一个当前阶段、详情显示另一个当前阶段；
- 页面刷新和接口重试不得生成阶段或历史记录。

## 11. 数据迁移

### 11.1 迁移原则

- 迁移前提供只读预览，至少显示受影响 SOP 版本数、任务模板数、学生数、阶段数、任务数、预计完成阶段数和异常数；
- 迁移脚本可重复执行；
- 重复执行不重复写阶段转换、计算批次或审计记录；
- 迁移不改变任务主状态、负责人、截止时间、进度、延期、改期、转派、取消或逾期历史；
- 迁移不重新套用 SOP，不复制学生任务；
- 迁移失败按学生或服务启用记录隔离，记录错误，不伪造进度；
- 正式迁移前必须备份并验证回滚方案。

### 11.2 阻塞属性迁移

- 既有 SOP 任务模板 `is_blocking` 默认迁移为 `true`；
- 既有任务实例 `is_blocking_snapshot` 默认迁移为 `true`；
- 既有任务实例 `source_type` 迁移为 `SOP`；
- 因此 S1 既有任务在迁移后仍需全部进入终态才能完成所属阶段，不会因默认非阻塞而提前推进。

### 11.3 阶段状态迁移

按阶段顺序处理每名已启用学生：

1. 第一阶段的起始基线为服务启用时间；
2. 若当前阶段全部阻塞任务已终态，标记为已完成；
3. 阶段完成时间优先取该阶段阻塞任务中最晚的终态时间；
4. 阶段完成时间不得早于本阶段开始时间或前一阶段完成时间；
5. 下一阶段开始时间等于系统确认前一阶段完成的有效时间；
6. 遇到第一个存在未终态阻塞任务的阶段，将其设为进行中；
7. 后续阶段设为未开始，即使其任务已提前完成，也等待前序阶段推进后再计算；
8. 若八阶段阻塞任务均已终态，则八阶段全部完成；
9. 无法可靠推导时间时使用迁移执行时间作为技术时间，并在转换记录中标记 `MIGRATION` 和“历史数据迁移”，不得冒充原业务操作时间。

### 11.4 未启用学生

- 不创建阶段状态或计算批次；
- 页面继续显示“服务未启用”；
- 后续启用时直接按 S2 新规则初始化。

### 11.5 迁移验收

- 预览结果与实际变更数量一致；
- 重复执行结果为零新增或明确跳过；
- 每名已启用学生最多一个进行中阶段；
- 阶段顺序无跳跃；
- 所有既有任务状态和历史保持不变；
- 异常学生显示“进度数据异常”，不进入猜测结果；
- 可按学生查看迁移批次和转换原因。

## 12. 阶段计算异常与补偿

### 12.1 异常识别

以下情况视为进度数据异常：

- 同一学生存在多个进行中阶段；
- 已完成阶段之后存在未完成的前序阶段；
- 阶段状态与时间字段不满足约束；
- 阶段数量或顺序快照异常；
- 阻塞任务缺失或关联到错误阶段；
- 任务终态与阶段状态无法按规则解释；
- 阶段转换记录重复或断裂。

### 12.2 页面处理

- 管理员看到“服务进度数据异常”、错误追踪 ID、最近计算时间和受控重算入口；
- 管家只看到“进度更新中”，不显示内部错误、数据结构或修复入口；
- 异常时保留学生基础信息和任务原始事实；
- 不自动生成猜测阶段、日期或完成原因。

### 12.3 重算

- 重算以任务状态、任务阻塞快照、阶段顺序和服务启用记录为事实源；
- 重算创建独立计算批次；
- 重算必须幂等；
- 重算不得修改任务事实；
- 重算产生的阶段变化标记 `RECALCULATION`；
- 正常任务事务失败时仍整体回滚，不能用异步补偿掩盖部分成功；
- 补偿重算仅处理迁移、历史数据或非事务性异常；
- 重算失败保留原异常状态并记录系统日志和审计。

## 13. 审计与时间线

### 13.1 阶段转换记录

阶段历史至少展示：

- 阶段开始；
- 阶段完成；
- 触发任务；
- 触发任务结果为完成或取消；
- 连续推进；
- 迁移推导；
- 异常重算。

每条记录显示事件类型、触发对象、香港时间、摘要和来源。

### 13.2 新增审计事件

至少记录：

- SOP 任务阻塞属性创建和修改；
- 因无阻塞任务导致的发布拒绝；
- 临时任务创建；
- 阶段启动和完成；
- 连续推进；
- 阶段计算失败；
- 迁移预览和执行；
- 管理员触发重算及结果；
- 阶段 `409 Conflict`；
- 管家越权访问学生进度。

### 13.3 审计字段

继承 S1，并至少包含：

- 操作人或系统；
- 角色；
- 学生、服务启用记录、阶段和触发任务 ID；
- 变更前后阶段状态；
- 阻塞属性；
- 触发类型和原因；
- 计算批次；
- 请求 ID；
- UTC 时间和香港时间展示能力。

审计和阶段转换记录只追加，不允许普通业务用户修改或物理删除。

## 14. 异常情况

| 场景                         | 系统处理                                     |
| ---------------------------- | -------------------------------------------- |
| SOP 某阶段没有阻塞任务       | 发布失败并定位到对应阶段                     |
| 服务启用生成阶段状态失败     | 整次启用回滚                                 |
| 非阻塞任务完成或取消         | 只更新任务，不推进阶段                       |
| 最后一个阻塞任务完成或取消   | 同事务完成当前阶段并启动后续计算             |
| 后续阶段阻塞任务已提前终态   | 按顺序连续推进                               |
| 前序非阻塞任务未完成         | 作为遗留任务监督，不回退阶段                 |
| 为已完成阶段创建阻塞任务     | 返回 `409`，不创建                           |
| 阶段推进同时创建阻塞任务     | 仅首个合法事务成功，后续返回 `409`           |
| 管家访问非本人负责学生       | 返回 `403`，不泄露学生或任务详情             |
| 学生不存在或已删除           | 返回 `404`                                   |
| 阶段数据加载失败             | 保留基础信息，阶段区域提供重试               |
| 阶段数据不一致               | 标记异常，不生成猜测数据                     |
| 正常任务和阶段事务失败       | 整体回滚并返回失败                           |
| 重算正在执行                 | 返回计算中状态，重复触发被拒绝或返回同一批次 |
| 重算失败                     | 保留异常状态，记录错误和审计                 |
| 重复完成、取消、创建临时任务 | 幂等返回首次结果或 `409`，不重复写入         |
| 页面刷新或重试               | 不重复生成阶段实例或转换记录                 |
| 历史时间无法推导             | 显示“历史数据迁移”，不伪造日期               |
| 筛选无结果                   | 显示空状态并可清除筛选                       |

## 15. 非功能要求

### 15.1 安全

- 复用 S0/S1 认证与 RBAC；
- 管家学生进度查询实施服务端行级权限；
- 任务详情继续独立校验当前负责人；
- 不因阶段聚合泄露无权任务；
- 重算和迁移仅管理员或受控系统进程可执行；
- 越权和关键拒绝写入安全审计。

### 15.2 一致性

- 任务终态和阶段推进在同一事务；
- 阶段顺序、单一进行中阶段和转换幂等由数据库约束与服务逻辑共同保证；
- 学生列表与详情复用统一统计口径；
- 阶段快照和任务阻塞快照不随 SOP 新版本变化；
- 任何页面刷新不得触发写入式阶段计算。

### 15.3 性能与索引

- 学生列表和管家本人学生列表必须分页；
- 为阶段状态、阶段顺序、学生、默认管家、阻塞属性、任务状态和截止时间建立适当索引；
- 避免按学生逐条查询任务造成 N+1；
- 连续推进最多处理固定八个阶段；
- 不设未经验证的响应时间承诺，在 S2 测试环境记录列表、详情和推进事务基线。

### 15.4 可观测性

- 阶段计算记录请求 ID、学生、起止阶段、推进数量、耗时和结果；
- 迁移和重算记录扫描数、成功数、跳过数、异常数和失败数；
- 事务回滚、唯一约束和乐观锁冲突具有结构化日志；
- 前端错误提示使用可关联的追踪 ID，不暴露堆栈和内部数据。

### 15.5 可用性

- 页面立即反馈任务操作后的阶段结果；
- 不要求固定轮询所有学生；
- 学生列表重新进入或主动刷新时获取最新数据；
- 详情任务操作成功后局部刷新摘要和阶段区域；
- 页面状态、交互反馈、响应式和无障碍要求沿用 S1。

## 16. 验收标准

### 16.1 SOP 与服务启用

- [ ] SOP 草稿任务可配置是否阻塞，新增任务默认阻塞；
- [ ] 复制新版本时阻塞属性完整复制；
- [ ] 任一阶段没有阻塞任务时发布失败；
- [ ] 已发布版本阻塞属性不可编辑；
- [ ] 启用服务一次生成八阶段及全部任务，第一阶段进行中；
- [ ] 其余七个阶段初始为未开始；
- [ ] 任务实例保存阻塞快照，后续 SOP 变化不影响既有学生；
- [ ] S2 不出现暂停、恢复、停用或重套 SOP 入口。

### 16.2 阶段推进

- [ ] 完成非阻塞任务不推进阶段；
- [ ] 取消非阻塞任务不推进阶段；
- [ ] 当前阶段仍有未终态阻塞任务时不推进；
- [ ] 最后一个阻塞任务完成后自动推进；
- [ ] 最后一个阻塞任务取消后自动推进；
- [ ] 任务终态和阶段变化在同一事务提交；
- [ ] 后续阶段任务可在阶段未开始时提前执行；
- [ ] 后续阶段阻塞任务已提前终态时允许连续推进；
- [ ] 连续推进严格按八阶段顺序；
- [ ] 八阶段完成后显示“8/8，全部阶段已完成”；
- [ ] 已完成阶段不回退、不重新打开；
- [ ] 页面没有手工推进、回退或强制完成按钮。

### 16.3 遗留任务和统计

- [ ] 已完成阶段的未终态非阻塞任务显示为前序遗留任务；
- [ ] 遗留任务继续按 S1 规则执行和计算逾期；
- [ ] 遗留任务不影响当前阶段推进；
- [ ] 阶段进度等于已完成阶段数除以 8；
- [ ] 当前阻塞数只统计当前阶段未终态阻塞任务；
- [ ] 逾期数覆盖全部阶段和遗留任务；
- [ ] 任务完成率排除已取消任务；
- [ ] 任务完成率分母为零时显示 `—`；
- [ ] 列表与详情统计一致。

### 16.4 临时任务

- [ ] 仅管理员可为已启用学生创建临时任务；
- [ ] 临时任务默认非阻塞，负责角色固定为管家；
- [ ] 当前和未开始阶段可新增阻塞任务；
- [ ] 已完成阶段只能新增非阻塞任务；
- [ ] 全部阶段完成后不能新增阻塞任务；
- [ ] 阻塞属性创建后不可修改；
- [ ] 临时任务可以待分配，也可分配给有效管家；
- [ ] 临时任务进入 S1 任务中心、监督、逾期和时间线；
- [ ] 并发创建阻塞任务和推进阶段时，过期操作返回 `409`；
- [ ] 相同幂等请求不重复创建临时任务。

### 16.5 页面与交互

- [ ] 不新增服务进度一级菜单和学生详情页签；
- [ ] 学生列表增量展示当前阶段、阶段进度、阻塞、逾期和遗留数；
- [ ] 支持已确认的筛选和排序，默认顺序不改变；
- [ ] 学生详情沿用 S1 顶部卡片和八阶段任务布局；
- [ ] 当前阶段默认展开，已完成和未开始阶段默认收起；
- [ ] 未开始阶段任务可展开并进入详情；
- [ ] 任务详情返回后保留筛选、分页和展开状态；
- [ ] 任务操作成功后立即刷新摘要和阶段区域；
- [ ] 加载、空数据、失败、无权限、未启用、异常和 `409` 状态完整；
- [ ] 页面视觉、组件和反馈方式与 S1 一致。

### 16.6 权限

- [ ] 管理员可查看全部学生服务进度；
- [ ] 管家通过“学生管理”只看到本人负责学生；
- [ ] 管家不能查看其他管家负责学生的服务进度；
- [ ] 更换默认管家后，进度权限立即转移；
- [ ] 原管家仍按 S1 任务负责人规则处理未转派任务，但不能访问完整学生进度；
- [ ] 管家页面只读，不显示管理员操作；
- [ ] 规划老师不能进入服务进度和阶段历史；
- [ ] 越权请求返回 `403` 且不泄露数据。

### 16.7 迁移、异常、幂等和并发

- [ ] 迁移前可预览影响范围和异常；
- [ ] 既有 SOP 模板和任务实例默认迁移为阻塞；
- [ ] 既有任务状态、负责人、截止时间和历史不被修改；
- [ ] 阶段状态按顺序推导，最多一个进行中阶段；
- [ ] 迁移重复执行不产生重复记录；
- [ ] 无法推导的时间显示迁移标记，不伪造业务日期；
- [ ] 数据异常时管理员可见异常，管家仅见更新中；
- [ ] 受控重算幂等且不修改任务事实；
- [ ] 正常任务事务失败时任务与阶段整体回滚；
- [ ] 并发任务终态、阶段推进和阻塞任务创建由乐观锁及 `409` 处理；
- [ ] 刷新和重试不重复生成阶段或转换历史。

### 16.8 审计

- [ ] 阻塞属性、临时任务、阶段转换、连续推进、迁移和重算均有审计；
- [ ] 阶段转换可追溯到触发任务或计算批次；
- [ ] 取消阻塞任务导致推进时保留取消原因和管理员；
- [ ] 审计包含前后值、对象、原因、请求 ID 和时间；
- [ ] 审计及转换记录不可由普通业务用户修改或物理删除。

### 18.2 风险与控制

| 风险                           | 影响                 | 控制                                                 |
| ------------------------------ | -------------------- | ---------------------------------------------------- |
| 把 S1 未实现能力当作现有能力   | S2 范围和验收失真    | 本文明确临时任务和管家学生访问均为 S2 新增           |

| 引入暂停或多角色任务           | 服务状态机和权限膨胀 | S2 明确不包含，继续沿用 S1 两态服务和管家任务        |
