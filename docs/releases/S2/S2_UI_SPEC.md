# S2 学生服务进度 UI 规格

## 设计基线

S2沿用S1现有管理端的信息架构、半透明白色卡片、圆角、蓝紫渐变阶段编号、状态标签、按钮层级、间距和反馈方式。不新增一级“服务进度”菜单，也不新增学生详情页签。

## 学生列表

- 管理员与管家都使用一级菜单“学生管理”。
- 管理员保留新建、负责人筛选和全量学生；管家只显示本人当前负责学生，隐藏全部写操作和负责人筛选。
- 列表增加当前阶段、`X/8`阶段进度，以及“阻塞 / 逾期 / 遗留”三项计数。
- 增加当前阶段、是否存在当前阻塞、阶段进度/阻塞/逾期排序；默认仍按S1最近建档顺序。
- 首次加载显示骨架屏；未启用显示`—`；计算异常不展示猜测进度。

## 学生详情

- 顶部继续使用学生身份区和服务状态，不增加页签。
- 管理员保留资料、负责人、启用、批量分配操作，并增加“新建临时任务”；管家只读。
- “服务与SOP”增加当前阶段、阶段进度、当前阻塞、全部逾期、前序遗留和任务完成率。
- “任务摘要”增加排除已取消任务后的完成率，分母为零显示`—`。
- 当前阶段默认展开；已完成和未开始阶段默认收起，用户可手工展开。
- 阶段标题展示状态、未终态阻塞数、任务总数、开始/完成时间、耗时和完成原因。
- 任务展示阻塞/非阻塞、SOP/临时、逾期和前序遗留标签。
- 从任务详情返回时携带列表筛选、分页、学生与展开阶段，返回后重新读取最新摘要和阶段事实。
- 阶段接口失败时保留学生基础信息，仅在八阶段区域显示错误和“重新加载”。

## 临时任务

- 表单字段：所属阶段、名称、说明、完成标准、当前截止时间、负责人和是否阻塞。
- 默认当前阶段、默认非阻塞、默认学生当前管家；负责人允许清空。
- 已完成阶段或八阶段全部完成时禁用阻塞开关，并解释原因。
- `409 Conflict`保留表单内容，提示重新加载阶段状态；保存中禁用重复提交。

## SOP编辑器

- 每项任务增加“阻塞阶段”开关，新增任务默认开启。
- 已发布和历史版本沿用整页只读。
- 文案明确：该阶段全部阻塞任务完成或取消后自动推进。
- 校验失败定位到缺少阻塞任务的阶段。

## 异常与权限状态

- 管理员看到错误代码、最近计算时间和“受控重算”，并说明重算不修改任务事实。
- 管家只看到“服务进度更新中”，不展示内部错误或修复入口。
- 计算异常或重算中隐藏阶段状态、时间和摘要数字，不展示猜测结果；任务原始事实仍可查看。
- 管家访问非本人负责学生时显示现有权限不足状态；后端返回`403`且写入安全审计。
