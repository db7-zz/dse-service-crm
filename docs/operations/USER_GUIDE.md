# DSE升学服务CRM V1.0使用手册

本文说明V1.0各角色如何进入系统和完成日常工作。页面是否显示、按钮是否可用，由角色权限、学生负责人关系和任务负责人关系共同决定。

## 1. 登录与通用操作

本地开发入口为 `http://localhost:3000`，API文档入口为 `http://localhost:3001/api/docs`。输入管理员创建的账号和密码登录；账号停用、锁定或密码错误时，系统不会泄露账号是否存在。

本地确定性演示数据只创建三个账号：管理员 `admin`、管家 `butler`、学生 `student`。三个账号共用本机 `.env` 中的 `SEED_DEMO_PASSWORD`，密码不写入Git。执行 `pnpm db:seed` 会先确认目标是本机名称包含 `dev` 的数据库，再清空并重建同一条管理员—管家—学生业务演示流程。

所有内部角色可从右上角“消息与待办”查看未读提醒。点击消息进入对应任务、资料、申请或问题；处理后可标记已读，也可一次全部已读。无权限页面会给出原因和返回工作区入口。

## 2. 管理员与业务负责人

### 2.1 工作区与监督任务

登录后默认进入“工作区”，集中查看在册学生、执行中任务、逾期任务、问题、申请和未读消息，并可直接进入常用业务页面。

“监督管理看板”是独立的任务监督页面。顶部数字可以直接筛选进行中、逾期、未分配和待处理提醒；还可按管家、学生、八个中文服务阶段、任务状态和截止时间组合筛选。

点击任务进入详情，可执行改期、转派、取消、不适用或安全重新打开。任何改期都保留原截止时间；转派保留原负责人和原因；取消、不适用和重新打开均进入任务时间线及审计日志。

### 2.2 维护账号与权限

进入“系统管理 → 人员账号”，按姓名、角色或状态筛选。新建账号后分配角色；停用前先查看其学生与未完成任务影响，并完成必要交接。账号密码只保存安全哈希，任何界面和日志都不显示明文密码。

### 2.3 维护SOP并启用学生服务

进入“SOP管理”创建或复制版本，配置固定八阶段、阶段完成条件和标准任务。发布前系统校验阶段顺序、阻塞任务、负责人角色和小时级完成时限；学生启用服务时只可选择已发布且启用的版本。

进入“学生管理”创建学生，可先建档、后分配管家和规划老师。启用服务后系统一次生成八个阶段和标准任务快照；模板后续变化不会覆盖已生成任务。

### 2.4 分配与交接

在学生详情更换管家或规划老师时必须填写原因。更换管家默认将其未完成任务转给新管家，已完成任务不变；人员关系、任务转派与通知在同一业务操作中记录。专项老师只分配到具体任务，不成为学生默认负责人。

### 2.5 完整档案与风险

在学生详情点击“完整业务档案”，维护英文名、学校、年级、届别、下一节点、当前/预测成绩和目标院校。风险可设为正常、关注或高风险并填写说明。暂停服务保留历史并停止自动生成；终止服务必须选择保留或取消未完成任务并填写原因。

## 3. 管家

### 3.1 我的任务

登录后默认进入“我的任务”，只显示当前分配给本人的任务。进入详情后可开始、更新进度、完成、报备延期、标记不适用并上传凭证。需要凭证的任务必须先上传文件，完成时必须填写结果；未分配、已取消或无权任务不能执行。

延期必须填写原因和预计完成时间，原截止时间不会被覆盖。超过当前截止时间的活动任务会自动进入逾期队列，并通知本人和管理员。

### 3.2 我的学生

“学生管理”仅展示本人担任默认管家的学生。学生详情汇总当前阶段、下一节点、阻塞任务、资料缺失、申请和团队；与本人无关的学生即使知道地址也无法访问。

### 3.3 资料管理

选择学生后查看核心资料完整度。可创建资料项、上传PDF/DOC/DOCX/JPG/JPEG/PNG文件、查看全部历史版本、审核通过或要求补交。每次上传产生新版本，不覆盖旧文件。

标记缺失时填写原因；设置补交计划时同时指定负责人和补交时间，系统创建或关联催收任务。人工归档到外部系统后只记录归档状态、时间与说明，外部归档失败不会抹掉CRM版本。

### 3.4 申请与问题

“申请管理”记录香港直申或JUPAS的院校、专业/志愿、轮次、截止日期、负责人和状态。每次状态变化填写说明；补件、面试、文书和Offer节点可以创建有负责人、有截止时间的关联任务。

遇到需要专业判断的事项，在“问题协同”选择学生并填写问题、背景和分类。管理员可直接回复、要求补充、转为专项任务或解决；关闭后仍有问题时可填写原因重新打开。

## 4. 规划老师

规划老师从“学生管理”进入本人负责的学生，只能查看相应业务档案和服务概览。可在“完整业务档案”维护当前/预测成绩与目标院校；不能执行管家任务，也不能看到其他学生。

## 5. 专项老师

专项老师在“我的任务”查看分配给本人的文书、面试、补件或其他专项任务。任务详情只提供交付所需的学生、要求、资料凭证和时间信息；不能浏览完整学生库、内部监督统计或无关资料。

## 6. 学生/家长入口

绑定学生档案的账号登录后进入 `/portal`。首页显示本人待办、缺失资料、当前阶段、下一节点、最新进度、申请摘要和待确认事项。

- “我的资料”：查看清单、审核意见和历史版本，上传或补交资料。
- “服务进度”：查看已完成阶段、当前阶段、下一节点和标记为对外可见的任务。
- “申请动态”：查看渠道、院校、专业、递交时间、当前状态和结果。
- “消息”：查看与本人有关的资料、阶段、申请和确认提醒。

学生/家长端不会返回管家完成率、内部逾期原因、管理员介入备注、员工绩效或其他学生数据。

## 7. 审计与问题处理

管理员从“系统管理 → 审计日志”按操作类型和对象筛选，查看操作者、角色、原因、请求标识、前后数据和时间。登录、权限、任务、阶段、资料审核/下载、申请、人员交接等关键行为均可追溯。

遇到版本冲突时刷新页面后重新提交；这类保护称为“乐观并发控制”，用于阻止较早打开的表单覆盖他人刚刚保存的数据。上传失败不会生成资料版本；网络失败时不要连续重复点击，先确认页面是否已经刷新出结果。

## 8. 开发与运维启动

首次启动按仓库README配置 `.env`、数据库迁移和种子。日常启动使用 `docker compose up -d postgres` 和 `pnpm dev`；停止应用开发进程后可用 `docker compose stop postgres` 停止数据库。上线前执行 `pnpm check`，数据库变更前先按 `BACKUP_RESTORE.md` 备份。
