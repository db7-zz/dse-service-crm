# S1 学生管理页面文字 UI 设计规范

## 1. 适用范围

本规范覆盖 Issue #4 的管理员端学生管理页面：

- 学生列表；
- 新建学生；
- 编辑学生基本资料；
- 学生详情；
- 默认管家和规划老师的分配、更换与取消分配。

S1 不依赖 Figma 文件、Figma 连接器或可交互原型。本文是该功能的设计与验收基线。

## 2. 视觉方向

- 借鉴 Apple 产品界面和官网的表达方式，但不复制具体页面；
- 使用充足留白、清楚的单屏重点、连续圆角和克制的半透明材质；
- 页面采用消费电子产品页式的信息节奏：先给出一个明确主标题，再逐层展示操作与数据；
- 主色使用克制的蓝色，状态色只用于服务状态、错误和冲突；
- 不继承 S0 的深色侧栏、紧凑表格和小圆角视觉，管理员工作区统一调整为浅色半透明导航和柔和背景；
- 动效保持轻量，并尊重 `prefers-reduced-motion`。

## 3. 信息架构与路由

| 页面     | 路由                                   | 主要任务                                     |
| -------- | -------------------------------------- | -------------------------------------------- |
| 学生列表 | `/workspace/students`                  | 搜索、筛选、分页、新建、进入详情             |
| 新建学生 | `/workspace/students/new`              | 最小建档，保存后进入详情                     |
| 学生详情 | `/workspace/students/{studentId}`      | 查看资料、负责人、服务和任务摘要，调整负责人 |
| 编辑学生 | `/workspace/students/{studentId}/edit` | 编辑姓名、电话和邮箱，保存后返回详情         |

管理员登录后的首选落点为学生列表。非管理员不显示学生管理导航，直接访问时显示无权限状态。

## 4. 字段与文案

### 4.1 学生列表

至少显示：

- 学生姓名与唯一学生编号；
- 电话与邮箱；
- 默认管家；
- 规划老师；
- 服务状态；
- 最近更新时间。

筛选项：

- 姓名、学生编号、电话或邮箱关键词；
- 服务状态；
- 默认管家；
- 规划老师。

### 4.2 新建与编辑

- 学生姓名：唯一必填字段；
- 联系电话：选填；
- 联系邮箱：选填；
- 默认管家：新建时选填，可留空；
- 规划老师：新建时选填，可留空。

新建页示例使用“黄翰”、`+852 6123 4567` 和 `hon.wong@example.com`。保存按钮文案为“保存并查看详情”，成功后直接进入该学生详情。

编辑页只更新基本资料。负责人在详情页独立调整，以强制填写变更原因并保留关系历史。

### 4.3 学生详情

信息卡片：

- 基本资料；
- 默认管家与规划老师；
- 服务状态与 SOP 版本；
- 任务摘要；
- 负责人变更记录。

后续功能入口：

- “启用服务”；
- “批量分配任务”。

Issue #4 只展示这两个入口并明确标记为后续开放，不实现服务启用、SOP 套用或任务分配。

负责人卡片必须提示：“更换默认管家不会自动转派已有任务”。

## 5. 关键交互

- 新建学生仅填写姓名即可保存；
- 管家和规划老师均可为空；
- 负责人分配、更换或取消分配均使用独立对话框，必须填写原因；
- 负责人保存后刷新详情和历史记录；
- 编辑资料和负责人变更均携带版本号；
- 收到 `409 Conflict` 时显示明确冲突提示与刷新操作；
- 负责人冲突刷新时保留已填写的变更原因；
- 未来功能按钮保持可见但禁用，并说明开放边界。

## 6. 页面状态

所有页面按适用场景覆盖：

- 首次加载骨架；
- 无学生空状态和“新建第一位学生”入口；
- 筛选无结果状态和“清除筛选”入口；
- 接口失败提示与重试；
- 无权限；
- 表单保存中；
- 保存成功；
- 普通操作失败；
- `409 Conflict` 与刷新；
- 分页越界自动回到最后一个有效页。

## 7. 响应式与无障碍

- 桌面端以宽表格和双列详情卡片为主；
- 中等屏幕将筛选区改为两列，详情卡片改为单列；
- 小屏幕将筛选、操作按钮、表单和任务摘要改为单列；
- 所有输入项具有可访问名称和清晰校验文案；
- 原生表格保留表头语义；
- 可交互元素支持键盘焦点；
- 状态不能只依赖颜色表达；
- 负责人历史使用语义化时间元素，并以香港时区展示；
- 链接、按钮和正文保持可读对比度。
